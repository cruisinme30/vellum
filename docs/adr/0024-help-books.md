## Context

The brief (section 12) and D29 in the PRD ask for three help books (user,
admin, developer) written in Vellum, shipped in the binary as
`vellum docs`, published with mdBook, with every block and Mermaid type
shown rendered and as source, a golden corpus generated from the guide,
a cookbook of twelve scenarios and contextual `?` help. The books
service (ADR 0013, D67) fixed the on-disk shape of a book.

## Decisions

### D100: three Vellum books in docs/, built into the binary

- The books are `docs/user.book`, `docs/admin.book` and
  `docs/developer.book`, in the shape D67 defines: `book.yaml` with
  `nodes` keyed by ULID, an mdBook `SUMMARY.md`, a `README.md`
  prefix chapter, `<slug>/README.md` for parents, and front matter with
  `id`, `title` and `vellum: 1` on every page.
- The cookbook is a part of the user guide, not a fourth book, so its
  recipes can link to the chapters they use.
- Links between chapters are relative `.md` links, so plain mdBook and
  the offline link checker both follow them. They move to
  `vellum://doc/<id>` cross-references once the books publish step
  resolves those.
- A new crate, `vellum-help` (foundation layer), embeds every page,
  summary and asset with `include_str!`. `vellum docs` lists the books,
  prints a book's contents or a page, and resolves a help ID. The table
  is generated by `cargo xtask help write`; CI fails if it is stale.
- The project website publishes the same folders with mdBook.

### D101: the guide's examples are the golden corpus

- Each example in the user guide is the block itself followed by a
  `markdown {corpus="kind/name"}` fence with its source (four backticks,
  so the source may contain a fence). `live=false` marks examples that
  cannot sit inside a chapter, such as front matter or whole pages.
- `cargo xtask help` (fast suite) fails when a live example differs
  from the block above it, when a block or Mermaid type in
  `xtask/src/help/coverage.rs` has no example, when `SUMMARY.md`,
  `book.yaml` and front matter disagree, or when derived files are stale.
- `cargo xtask help write` writes each example to
  `corpus/guide/<kind>/<name>.md`. The format thread owns the expected
  outputs beside them (`.ast.json`, `.canonical.md`), and render and
  export add `.html` and the rest under the same names.
- Corpus inputs are test data: markdownlint, Vale and the link checker
  skip `corpus/`, and `REUSE.toml` covers their licence.
- Every Mermaid example was rendered with Mermaid 11 when written; the
  pixel fixtures from the render thread keep them honest from then on.

### D102: contextual help IDs, translations and videos

- The app's `?` button knows only a stable help ID such as
  `editor.slash-menu`. `docs/help-anchors.yaml` maps each ID to
  `<book>/<page>#<anchor>`; `cargo xtask help` checks every target
  heading exists. Target headings carry a custom `{#anchor}` so
  rewording a heading never breaks help. IDs are never renamed or reused.
- Translations are copies of the books under `docs/i18n/<locale>/` with
  the same paths and page IDs, so a help ID resolves in every language
  and falls back to English. Interface strings stay in Fluent.
- The ten videos (R-HG-5) are recorded from the cookbook and chapters
  listed in the developer guide's "Maintaining the help books" page,
  against the Northstar demo workspace, once the matching features land.
- Search, per-release versions, "was this helpful" and edit-on-GitHub
  links (R-HG-4) are site features of the mdBook publish step and the
  in-app reader; the books need nothing extra for them.

## Consequences

- A pull request that adds a block must add its example to the guide and
  its name to `coverage.rs`, or the fast suite fails.
- Chapters describe 1.0 as the brief specifies it; threads update the
  matching chapter in the same pull request when behaviour differs.
- The markdownlint configuration now ignores `docs/*.book/SUMMARY.md` (mdBook uses `#`
  for part titles), reads the page title from front matter only for
  MD025, and allows bare URLs (`::: link <url>` takes one).
